## Locales configurados

Definidos en `app/i18n/routing.ts` (`routingConfig`, fuente única de verdad) y consumidos desde `nuxt.config.ts` (bloque `i18n`), en vez de duplicar la tabla en ambos sitios:

| Next (`routingConfig`) | Nuxt (`i18n.locales[]`) |
|---|---|
| `locales: ['es-ES', 'en-US']` | Un objeto `{ code, iso, name, file }` por cada entrada |
| `aliases: { 'es-ES': 'es', 'en-US': 'en' }` | `code` = alias corto (`es`/`en`) — es lo que `@nuxtjs/i18n` usa como prefijo de URL, jugando el mismo rol que `aliases` en next-intl |
| locale completo (`es-ES`/`en-US`) | `iso` — usado para `<html lang>`/SEO, no para el prefijo de ruta |
| `default: 'es-ES'` | `defaultLocale: 'es'` (alias del default) |
| `localePrefix: 'as-needed'` | `strategy: 'prefix_except_default'` — el locale por defecto no lleva prefijo (`/`), el resto sí (`/en/...`) |

Verificado: `curl /` (es, sin prefijo) → 200; `curl /en` → 200; `curl /es` → 404 (correcto, `prefix_except_default` no expone el default con prefijo).

## ⚠️ Gotcha: `restructureDir` se resuelve contra `rootDir`, no contra `srcDir`

`@nuxtjs/i18n` v9+ busca sus archivos (`langDir`, detector de locale custom...) en `resolve(rootDir, restructureDir ?? 'i18n')` — **siempre relativo a la raíz del proyecto**, no a `srcDir` (`app/`, que es el `srcDir` de este proyecto en Nuxt 4). Por defecto esto crearía la convención en un `i18n/` nuevo en la raíz, sibling a `app/`/`server/`/`shared/` — lo cual rompería la correspondencia de carpetas ya documentada en `CLAUDE.md` (`app/i18n/` ↔ `src/i18n/` de Next).

**Fix**: se configura explícitamente `restructureDir: 'app/i18n'` en `nuxt.config.ts` — es solo un string que se concatena a `rootDir`, así que apuntarlo a `'app/i18n'` mantiene los mensajes dentro de `app/i18n/locales/` sin crear una carpeta nueva en la raíz. Si se resetea esta opción sin saber esto, `npm run dev` vuelve a fallar con `ENOENT: no such file or directory, open '.../i18n/locales/es.json'`.

## ⚠️ Gotcha (Fase 7): el carácter `@` en un mensaje rompe el compilador de vue-i18n

vue-i18n reserva `@` para "mensajes enlazados" (`@:key`, `@.modifier:key`). Un mensaje con un `@` literal fuera de esa sintaxis (p.ej. un placeholder de ejemplo `"tu@email.com"`) hace que el compilador lance `Message compilation error: Invalid linked format` — no en build, sino **en cada request** que renderice ese mensaje (confirmado con `curl`, `500` sistemático). El escape documentado (`%@`) no lo resolvió en pruebas. Solución aplicada: evitar el `@` en el contenido del mensaje directamente (placeholder descriptivo en vez de un email de ejemplo) — ver `.project_docs/components.md`.
